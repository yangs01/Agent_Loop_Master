# 《Claude Code 原理解析》系列 · 第 1 篇
## 设计哲学：为什么"少即是多"

### 写在前面

如果你写过 Agent，大概率经历过这样的演化：先用 ReAct 跑通一个 demo，然后开始堆——加一个 planner、加一个 memory 模块、加一个 task queue、加一套 tool router、再上一个向量数据库……最后你得到一个有几十个类、调试起来像考古的系统，而它解决问题的能力，未必比最初那个 demo 强多少。

Claude Code 走了相反的路。**理解它的第一步，不是看它做了什么，而是看它克制着没做什么。**

这一篇不讲任何具体机制，只确立一个贯穿全系列的判断标准：**复杂度应该放在哪里。**

---

### 一、一代 Agent 框架的"复杂度错配"

我们可以把一个 Agent 系统的复杂度，粗暴地分到三个地方：

1. **框架层**：调度逻辑、状态机、规划器、记忆模块、工具路由……你写的代码
2. **模型层**：模型本身的推理、规划、纠错能力
3. **上下文层**：你喂给模型的信息——提示词、文件、历史、工具结果

2022–2023 年那一代 Agent 框架（AutoGPT、BabyAGI 乃至早期 LangChain Agent）的共同假设是：**模型不够聪明，所以框架要替它把事情安排明白。** 于是规划、反思、任务拆分、记忆管理，全都被实现成了框架里的显式模块。

这个假设在当时不算错。但它带来一个结构性问题——**框架层的复杂度，不会随模型变强而自动消解，反而会变成阻碍。** 当模型本身已经能做多步规划时，你那个硬编码的 planner 反而成了天花板：它只能按你想到的方式拆任务，模型想到的更好的拆法，被框架挡在外面了。

这就是**复杂度错配**：你把赌注押在了一个正在快速贬值的地方（框架），而不是一个正在快速升值的地方（模型）。

---

### 二、Claude Code 的核心下注：把复杂度交还给模型和上下文

Claude Code 的设计哲学，本质上是一次重新下注：

> **框架层做到尽可能薄，把规划、决策、纠错的复杂度，全部交还给模型；把"喂什么信息"的复杂度，交给上下文工程。**

具体表现为三个"反直觉"的选择，它们也正是后续各篇的主题：

- **没有独立的 planner。** 规划这件事，不是框架的一个模块，而是模型在循环里自然产生的行为。（→ 第 2 篇）
- **没有几十个专用工具。** 只有少量通用原子能力，外加一个 `bash` 当万能逃生舱。能力的扩展靠组合，而非靠堆 API。（→ 第 3 篇）
- **没有默认的向量数据库。** 对代码这种可精确匹配的语料，它更信任 `grep`/`glob` 这类确定性搜索，让模型像人一样去翻代码。（→ 第 5 篇）

每一个选择单独看都"少做了点什么"，但合起来，你得到的是一个**随模型能力增长而自动变强**的系统。模型越强，那层薄框架的天花板就越高——因为它几乎没有天花板。

这就是"少即是多"的真正含义：**少做的部分，不是被省略，而是被让位给了更会增长的东西。**

---

### 三、一个判断标准：谁来承担"聪明"

读完全系列，你会发现 Claude Code 的几乎每一个设计争论，都可以归结到同一个问题：

> **这件事，应该由框架来保证，还是由模型来发挥？**

- 任务怎么拆？→ 让模型在循环里自己拆，而不是写一个 planner
- 出错了怎么办？→ 把报错喂回去让模型自己改，而不是写一堆异常分支
- 找哪个文件？→ 给模型搜索工具让它自己找，而不是预先建好索引投喂

这里面有一条清晰的价值取向：**凡是模型能做好的，就不要在框架里硬编码。** 框架的职责退化为三件最朴素的事——**驱动循环、暴露工具、管理上下文。** 其余的"聪明"，全部外包给模型。

这不是偷懒，而是一种对趋势的押注：在一个模型能力每隔几个月就跳一级的时代，**最好的架构，是那个能最大限度"蹭"到模型增长红利的架构。**

---

### 四、代际差异：一句话定位

为了让你对坐标系有感觉，提前用一句话标定几个参照物（后续篇章会展开）：

- **ReAct**：证明了"推理 + 行动"交替的范式可行，但停留在单步循环的原型。
- **AutoGPT / BabyAGI**：把规划、记忆做成了重型框架模块——**复杂度押在框架层**。
- **LangChain Agent**：提供了强大的可组合抽象，但抽象本身也是需要学习和对抗的复杂度。
- **Claude Code**：把框架压到最薄，**复杂度押在模型层和上下文层**——这是它和前几者的代际分野。

---

### 小结与下一篇预告

这一篇没有讲任何"机制"，因为机制是结论，哲学才是前提。记住一句话就够了：

> **Claude Code 的每一个"简单"，背后都是一次"把复杂度交给更会增长的那一方"的主动选择。**

下一篇，我们拆开这套哲学的心脏——**那个看似平平无奇的 while 循环，凭什么不需要状态机、不需要 planner，就能撑起整个系统。**
