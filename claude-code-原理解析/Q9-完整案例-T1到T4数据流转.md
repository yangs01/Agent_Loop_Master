# Q9 · 一条数据流走完 T1→T4（主 agent / 子 agent / 外部存储）

> 配套：`Q8-详解-一个case逐帧看破法123.md`。Q8 是按"窗口占用百分比"分帧；这一篇换个角度——
> **盯住数据本身的流转**：一块内容从进来，到被丢/被搬/被折/被砸，到最后落在哪。
>
> 先钉一个前提：**压缩只有 4 层，没有 T5。**
> - T1 微压缩（每轮，纯删，不调模型）
> - T2 归档（近阈值，搬家，不调模型）
> - T3 折叠（~75%，摘要一段曲折，调模型）
> - T4 全量（~90%，整段历史砸成 9 段摘要，调模型）
>
> 本篇每一帧固定回答你的 5 个问题：
> 1. **主 agent 上下文里有什么**
> 2. **丢弃/处理了什么**
> 3. **主 agent 上下文剩下什么**
> 4. **子 agent 读了什么 / 剩什么 / 返回什么**
> 5. **外部存储存了什么**

---

## 舞台设定

- **任务**：给博客的评论系统加"楼中楼"嵌套回复，别改坏现有测试。
- **窗口预算**：200k token（下面百分比都相对它）。
- **三个主体**：
  - **主 agent**：全程干活的那个，它的窗口是我们要盯的舞台。
  - **子 agent**：临时克隆出去干脏活的分身，进小黑屋、只带一句结论回来、用完销毁。
  - **外部存储**：磁盘上的 `CLAUDE.md` / 代码文件 / 迁移文件——**永远在窗口之外**。

**贯穿全文的一张符号表**（后面快照都用它）：

```
🟦 缓存前缀（系统提示+工具定义）  ← 永远不动，动了缓存失效要重付钱
🟩 用户指令（逐字）              ← 宪法，永远留
🟨 有效结论 / 现行成果           ← 当前还在用的
🟧 临时噪声（工具原始输出）       ← T1 的猎物
⬜ 占位符（已清理的坑位）
🗄️ 归档区（不占窗口，T2 搬进去的）
💾 磁盘（窗口之外，破法三落盘的）
```

同上，🟦 + 🟩。

### 4️⃣ 子 agent

空。

## 帧 1 · T1 微压缩 + 子 agent 勘探（占用 ~5% → 峰值冲高又被 T1 压回 ~30%）

主 agent 意识到"搞清楚评论系统现状"是脏活（要 grep、翻 20 个文件、看 14 个测试），**不自己翻，派子 agent 去翻**。

### 4️⃣ 子 agent：读了什么 / 剩什么 / 返回什么

| 阶段 | 内容 |
|---|---|
| **子 agent 拿到的输入** | 一句指令："勘探评论系统实现：数据模型/增删查改在哪些文件、DB 有没有层级字段、现有测试覆盖了啥。**只返回结论，别把文件内容贴回来。**"（+ 共享的缓存前缀🟦） |
| **子 agent 在小黑屋里读了什么** | grep 十几个关键词、`Read` 了 ~20 个文件、逐个看了 14 个测试用例——**这些原文只存在于子 agent 自己的窗口** |
| **子 agent 自己窗口里剩什么** | 干完就不重要了，因为它**马上要销毁** |
| **子 agent 返回给主 agent 的** | 一段浓缩结论（👇），**不是 20 个文件** |
| **子 agent 的下场** | **销毁**，那 20 个文件原文随之蒸发，从没进过主窗口 |

子 agent 带回的结论（这段才进主窗口）：
```
· 逻辑在 CommentService.js、models/Comment.js
· comments 表字段：id/post_id/author/body/created_at —— 没有 parent_id（这就是要加的）
· 相关测试 14 个，在 test/comment.test.js
· API 入口 routes/comments.js
```

### 1️⃣ 主 agent 上下文里有什么（子 agent 回来后，且期间每轮跑 T1）

主 agent 自己也做了几步（列目录确认路径、试读了个文件确认结论），产生了🟧临时噪声：

```
🟦 系统提示 + 工具定义
🟩 用户第1轮指令
🟨 子agent勘探结论（上面那段）
🟧 [tool: list_dir 完整目录树 · 40 行]      ← 已经用完（路径确认了）
🟧 [tool: read Comment.js 全文 · 60 行]     ← 只为核对"没有 parent_id"
```

### 2️⃣ T1 丢弃了什么（每轮机械清理，不调模型）

- 🟧那坨 40 行 `list_dir` 目录树 → 目的达成（路径已确认）→ **整块换占位符 ⬜**
- 🟧那 60 行 `read Comment.js` → 只用来核对结论，结论已进🟨 → **截断成占位符 ⬜**

> T1 只做机械判断："这次工具调用目的达成了没 / 有没有更新版本"，**不理解语义、不写新文字、直接删或占位**。

### 3️⃣ 主 agent 剩下什么（T1 之后，占用压回 ~30%）

```
🟦 系统提示 + 工具定义
🟩 用户第1轮指令
🟨 子agent勘探结论
⬜ [list_dir 已清理]
⬜ [Comment.js 已清理 · 需要时重新 Read]
```

### 5️⃣ 外部存储
仍空（任务刚起步，还没有阶段成果值得落盘）。

> **本帧数据流一句话**：20 个文件的原文 → **只进子 agent 小黑屋** → 子 agent 销毁蒸发；主 agent 自己那点勘探噪声 → **T1 当场删掉**。窗口里只留一段结论。

## 帧 2 · T2 归档（占用 ~30% → 逼近 60% → 搬家后回落 ~45%）

开始真动代码。主 agent 按需把文件拉进来自己改。

### 1️⃣ 主 agent 上下文里有什么（干了一串活，历史变长）

干活流水：
1. 写迁移脚本 v1 → 跑 → 失败（外键约束写错）
2. 改迁移 v2 → 跑 → 过
3. 改 Comment 模型加 parent_id
4. 写了第一版"拉评论树"代码 → 自测发现思路不对（JS 循环查库太慢）→ **推翻**

于是窗口堆成这样（占用逼近 60%）：
```
🟦 系统提示 + 工具定义
🟩 用户第1轮指令
🟨 勘探结论
🟧 迁移脚本 v1 全文（已被 v2 取代）
🟨 迁移脚本 v2 全文（现行）
🟧 第一版树代码全文（已推翻）
🟨 "parent_id 已加好"这个事实
🟧 最近几轮 tool 结果
```

### 2️⃣ T2 归档了什么（搬家，不调模型）

把**最老、已经没用**的整条消息，从"活动窗口数组"**搬到归档数组**（不是删，是移走）：
- 🟧 迁移脚本 v1（已被 v2 取代）→ 🗄️
- 🟧 第一版被推翻的树代码 → 🗄️
- 🟧 帧 1 残留的勘探过程碎片 → 🗄️

> T1 是"删"，T2 是"搬"。搬进🗄️归档区后**不再占用窗口**，但万一要回溯还能找到。**同样不调模型**，纯内存搬家。

### 3️⃣ 主 agent 剩下什么（T2 之后回落 ~45%）

```
🟦 系统提示 + 工具定义
🟩 用户第1轮指令
🟨 勘探结论（精简）
🟨 迁移脚本 v2 + "parent_id 已加"事实
🟧 最近几轮 tool 结果（还没到该压的时候）
🗄️ 归档区：迁移v1、树代码v1、勘探碎片   ← 不占窗口
```

### 4️⃣ 子 agent
本帧没派。

### 5️⃣ 外部存储（破法三第一次落盘）

主 agent 顺手把阶段成果写进磁盘：
```
💾 CLAUDE.md：
   - [x] DB: comments 表已加 parent_id（迁移 20260712_add_parent_id.js 已过）
```

> **本帧数据流一句话**：作废的旧版本（v1、推翻的代码）→ **T2 搬进归档区**（不占窗口但可回溯）；确定的成果（parent_id 已加）→ **顺手写进磁盘**。

## 帧 3 · T3 折叠（占用 ~60% → 75% → 折叠后回压 ~65%）

用户追问"楼中楼没生效"，进入 debug 拉锯。

### 1️⃣ 主 agent 上下文里有什么（debug 七八轮，日志暴涨）

```
🟦 系统提示 + 工具定义
🟩 用户第1/2/3轮指令
🟨 勘探结论 + 迁移事实
🟧 试A：普通JOIN → 只出一层 → 失败日志 40 行
🟧 试B：应用层递归 → N+1 慢 → 失败日志
🟧 试C：递归CTE → 语法错 → 40 行 SQL 报错
🟨 试D：修正CTE → 通过
```

占用逼近 75%。

### 2️⃣ T3 折叠了什么（这是压缩账里**第一次真调模型**）

分两级：
- **过 60% 先做便宜的截断**（还是 T1 那类）：每坨失败堆栈只留关键那一行，比如 40 行 SQL 报错 → 压成 `CTE 语法错：near 'RECURSIVE'`。
- **过 75% 升级 T3**：把"试A失败→试B失败→试C失败→试D通过"这**一整段曲折**读懂后**摘要成一句**：

```
🟨 "拉评论树：应用层递归导致 N+1（慢）→ 改用递归 CTE，修正语法后测试通过。"
```

> **为什么这里必须调模型？** 因为要"**读懂那段弯路再写成一句人话**"——这是**产出新文字**，T1/T2 那种"删/搬"做不到。这就是 T1/T2 与 T3/T4 的分水岭。

### 3️⃣ 主 agent 剩下什么（T3 之后回压 ~65%）

```
🟦 系统提示 + 工具定义
🟩 用户第1/2/3轮指令
🟨 勘探结论 + 迁移事实
🟨 [debug 折叠成一句] ← 原本七八轮 + 几百行日志
🟨 最近一次成功测试结果
🗄️ 归档区（延续）
```

### 4️⃣ 子 agent
本帧没派（T3 主 agent 自己折叠即可）。

### 5️⃣ 外部存储
T3 是压缩动作，**本身不碰外部存储**（压缩和落盘是两条独立的线）。
但主 agent 在"试D 递归 CTE 通过"这一刻，通常会**顺手落盘**一条：
```
💾 CLAUDE.md += - [x] 拉评论树：递归 CTE 实现，测试通过
```
（落盘时机由主 agent 自主决定，跟占用百分比 / 触没触发 T3 **无关**）

> **本帧数据流一句话**：几百行失败日志 → **先截断（免费）再折叠成一句（调模型）**。弯路的"过程"没了，"结论"留下。

## 帧 3.5 · 破法三主动落盘（占用 ~78%，非压缩动作）

用户第 4 轮（关键决策）："嵌套别无限套，**最多 5 层**。"

主 agent 主动把阶段成果写盘（这是**任务账**，写笔记要调模型，但和压缩无关）：

### 5️⃣ 外部存储（这一帧的主角）
```
💾 CLAUDE.md：
   ## 评论系统重构 · 进度
   ### 已完成
   - [x] DB: comments 表加 parent_id（迁移已过）
   - [x] 拉评论树：递归 CTE 实现，测试通过
   ### 待办
   - [ ] 前端渲染嵌套评论（楼中楼 UI）
   - [ ] 补测试：嵌套回复用例
   ### 关键决策
   - 最大嵌套深度 = 5 层（用户第4轮明确要求）
   - 查询方案：WITH RECURSIVE（放弃应用层递归，因 N+1）
```

### 本帧题眼
> 写完这一刻，关键事实**同时活在两个地方**：
> - 对话历史里（窗口内，之后会被压缩动到）
> - 💾 磁盘上（`CLAUDE.md`，压缩碰不到）
>
> 这份"双份保险"，就是帧 4 T4 之后能救命的东西。

## 帧 4 · T4 全量压缩（占用 ~90% → 断崖砸回 ~35%）

前端又写了一大段，占用一路涨到 90%。T1/T2/T3 都削不动了（能搬的早搬、能折的早折）。触发**最后的重锤 T4**。

### 4️⃣ 子 agent 再登场（这次是"压缩子 agent"）

| 阶段 | 内容 |
|---|---|
| **压缩子 agent 拿到的输入** | 主 agent **当前整段历史** + 一份 **9 段结构化模板**。**和父 agent 共享缓存前缀🟦（缓存命中，不重付前缀的钱）** |
| **子 agent 在草稿纸(scratchpad)上干什么** | 按时间顺序把整段对话捋一遍，边捋边想"哪些必须留、哪些能扔"——这是**思考过程** |
| **草稿纸的下场** | 注入回主窗口前，**scratchpad 被丢弃**——思考改善了质量，但**不占用刚腾出来的预算** |
| **子 agent 返回的** | 按 9 段模板写出的**结构化摘要** |

### 1️⃣ 主 agent 上下文里有什么（T4 之前，~90%）
```
🟦 系统提示 + 工具定义
🟩 用户第1/2/3/4轮指令
🟨 一堆折叠过的结论
🟧 前端渲染的多轮试错、累积的 tool 结果、各种中间态  ← 几万 token
```

### 2️⃣ T4 砸掉了什么
中间那一大段**陈旧历史**（🟧前端多轮试错 + 累积工具结果 + 早期中间态）：**几万 token → 几百 token 的摘要**。

### 3️⃣ 主 agent 剩下什么（9 段模板**强制不许丢**）

摘要必须含这 9 段，其中**第 6 段是命门**：

| # | 段 | 本例具体内容 |
|---|---|---|
| 1 | 原始需求 | 重构评论系统支持嵌套，不改坏测试 |
| 2 | 关键技术概念 | 递归 CTE、parent_id、最大 5 层 |
| 3 | 相关文件 | Comment.js、CommentService.js、routes/comments.js、迁移、comment.test.js |
| 4 | 报错与修复 | N+1→递归CTE；CTE 语法错→修正后过 |
| 5 | 解决思路 | 放弃应用层递归，用 SQL 递归查 |
| 6 | **所有用户消息(逐字)** | 第1轮宪法 + 第2/3轮 debug + **第4轮"最多5层"** |
| 7 | 待办 | 前端渲染楼中楼、补嵌套测试 |
| 8 | 进行中 | 前端渲染 UI |
| 9 | 下一步 | 折叠/展开、跑全量测试 |

T4 之后的窗口（~35%，断崖下跌）：
```
🟦 系统提示 + 工具定义        ← 地板：常驻
🟨 9段结构化摘要             ← 几万token被砸成这一段
🟩 用户1/2/3/4轮指令(逐字)   ← 摘要第6段保住
🟧 最近1~2轮原始消息         ← 最新指令/最后测试结果，不压
```
> 掉不到 0，是因为上面这几行是"地板"（前缀+摘要本身+近期消息都得占 token）。

### 5️⃣ 外部存储
**完全没被 T4 碰到**——💾 CLAUDE.md 那份笔记压根不在窗口里。（这点马上救命。）

> **本帧数据流一句话**：整段历史 → **交给压缩子 agent**（共享缓存前缀）→ 草稿纸思考后丢弃 → 只带回 9 段摘要。用户四轮原话**逐字**被摘要第 6 段保住。

## 帧 5 · 破法三兜底 + 收尾锯齿波（你要的"第 5 段"）

### 假设最坏情况
T4 摘要**漏了**一条细节："前端要处理**折叠/展开状态**"。（摘要再结构化也总有漏。）

### 有破法三 = 有惊无险
压缩一结束，主 agent 第一件事是**读回自己写的笔记**：
```
读回 💾 CLAUDE.md →
   待办：前端渲染楼中楼、补测试
   关键决策：最大 5 层
   （"折叠/展开"当初也记进了笔记 → 这里直接读回补上）
```

### 1️⃣3️⃣ 读回后主 agent 上下文（~40%，信息完整）
```
🟦 系统提示 + 工具定义
🟨 9段摘要
🟩 用户1/2/3/4轮指令(逐字)
💾→🟨 刚读回的 CLAUDE.md 笔记（补回摘要漏掉的"折叠/展开"）
🟧 近期消息
```

### 收尾
主 agent 拿着完整信息做完前端（含折叠/展开、限 5 层）、补测试、全量测试通过。
占用又从 ~40% 涨回高位 → T1/T2/T3 削峰 → 逼近 90% 再来一次 T4 → 再砸回 ~35%……**锯齿波循环**，直到完工。

> **本帧数据流一句话**：摘要漏的细节，**从磁盘读回补上**——因为它从来不只活在对话里。这就是"保真度 vs 预算"死结被拆开的地方。
